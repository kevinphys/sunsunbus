# 硬體感測盒 CSV 格式（對照組）

感測盒是手機量測的「標準答案」：固定在車上（不會被拿起來、不會滑動），用來檢查手機在支架、座椅、手持三種放法下讀數準不準。分析工具 `sunsunbus compare-box` 讀這個格式。

## 檔案格式

UTF-8 純文字，開頭可以有 `#` 開頭的註解行（`key=value`，空白分隔），接著是一行欄位名稱，之後每筆取樣一行。

```
# sunsunbus-box v1
# device=esp32-mpu6050 rate_hz=100 accel_range_g=4 gyro_range_dps=500 mount=seatback
t_ms,ax,ay,az,gx,gy,gz
12034,0.1234,-0.0456,9.8061,0.12,-0.34,0.05
12044,0.1301,-0.0398,9.8102,0.10,-0.31,0.07
```

| 欄位 | 必要 | 單位 | 說明 |
|---|---|---|---|
| `t_ms` | ✓ | ms | 盒子自己的時鐘（例如 ESP32 的 `millis()`），只要單調遞增即可 |
| `ax, ay, az` | ✓ | m/s² | **含重力**的三軸加速度（靜止平放時 `az ≈ +9.81`） |
| `gx, gy, gz` | 建議 | deg/s | 陀螺儀；有的話靜置判斷比較準 |
| `unix_ms` | 選用 | ms | 盒子有 GPS 或 RTC 時填真實時間（Unix epoch），可直接對時 |
| `lat, lon, speed` | 選用 | deg, deg, m/s | 盒子自己的 GPS；沒有的話分析時借用手機的 GPS |

- 建議取樣率 50 至 100 Hz，每筆間隔不需要完全固定。
- 軸向不需要對齊車子：分析工具會像手機一樣自動找重力方向與前進方向。只要**固定牢靠**，不要晃動。
- 加速度量程建議 ±4 g 以上（敲擊對時時會有 2 至 3 g 的尖峰）。

## 與手機對時

盒子和手機的時鐘不同，分析時用以下方式對齊（`analysis/sunsunbus/hardware.py`）：

1. **有 `unix_ms`**：直接換算。
2. **敲擊對時（推薦）**：上車開始記錄後，在手機上按「🔔 對時敲擊」，接著把手機和盒子疊在一起，在硬的表面上敲一下。兩邊都會出現一個超過 1 g 的尖峰，工具會在手機標記前後 15 秒內找這個峰。
3. **細對時**：在粗對時結果附近 ±5 秒內，用「水平加速度大小」做互相關，找出最佳位移。

都沒有時，工具假設兩邊同時開始，並把搜尋範圍放大到 ±60 秒。

## 比較的輸出

`uv run sunsunbus compare-box <手機趟次> <盒子.csv>` 會輸出：

- 對時方式與 offset
- 兩邊都穩定的時段中，`a_long`、`a_lat`、`jerk_mag` 的相關係數與 RMSE
- 各類事件的一致率（同類型、峰值時間差 1.5 秒以內算同一個事件；一致率 = 配對成功數 ÷ 兩邊事件聯集）
- 疊圖 PNG
